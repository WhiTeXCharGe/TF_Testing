TIMEFOLD SCHEDULER — WEBAPP FILE EXPLANATION
================================================================================

Root level
----------
package.json
  NPM manifest. Dependencies: react, react-dom, react-router-dom, xlsx (SheetJS),
  exceljs, file-saver, js-yaml, axios.
  Dev deps: vite, @vitejs/plugin-react, typescript, @types/*.

tsconfig.json
  TypeScript configuration for the browser bundle. Path alias "@/" maps to "src/".
  strict: true, jsx: react-jsx, noEmit: true (Vite handles emit).

tsconfig.node.json
  Separate TS config for Vite config file (composite build).

vite.config.ts
  Vite build configuration. Registers @vitejs/plugin-react, sets up "@/" alias.
  Excludes exceljs from optimizeDeps (Node.js built-ins incompatibility workaround).

index.html
  Entry HTML. Mounts the React app at <div id="root">.

pipeline.md
  Cloud execution pipeline design for the Timefold solver (Java 21).
  Covers GCP Cloud Run Jobs (recommended), AWS ECS Fargate, Fly.io.
  Includes HTTP API design, GCS storage layout, cost estimates.

explanation.txt
  This file. Documents every source file in the project.

src/
================================================================================

src/main.tsx
  React entry point. Creates root, wraps App in StrictMode, imports global CSS.

src/App.tsx
  Top-level router. Uses BrowserRouter + React Router v6 Routes.
  Routes:
    /                       → RunLogPage  (landing — the run log)
    /gantt/:runId           → GanttPage   (input schedule)
    /gantt/:runId/:view     → GanttPage   (view = "result")
    /settings               → SettingsPage
  Wraps all routes in Layout (sidebar + topbar).

  NOTE (mock model): there is no "dataset" concept and no backend. Each Run is
  one local folder ./runs/<id>/ with input/ + output/ subfolders, SIMULATED in
  the browser via localStorage (services/runStore.ts). A browser cannot write
  real disk folders; to make them real later, swap runStore.ts for the File
  System Access API or a small local Node backend — the UI won't change.

--------------------------------------------------------------------------------

src/utils/
--------------------------------------------------------------------------------
dateUtils.ts
  Pure date helpers (no external deps):
    parseDate(s)        — "YYYY/MM/DD" or "YYYY-MM-DD" → Date (local midnight)
    formatDate(d)       — Date → "YYYY/MM/DD"
    toKey(d)            — Date → "YYYY-MM-DD" (for Map keys)
    dateRange(s, e)     — Date[] from start to end inclusive
    isWeekend(d)        — true if Sat or Sun
    dowAbbr(d)          — "Mon", "Tue", …
    monthName(d)        — "Jan", "Feb", …
    formatTimer(sec)    — seconds → "HH:MM:SS"
    formatElapsed(s, e) — two ISO strings → "1h 23m" or "45m 10s"
    nowLabel(iso)       — ISO string → "YYYY/MM/DD HH:MM"

colorUtils.ts
  Deterministic color assignment (mirrors Python stable_palette_color()):
    hashStr(s)              — XOR hash → unsigned 32-bit int
    normalizeModuleCode(c)  — strip suffix after first '_'
    moduleColor(baseCode)   — index into 30-color MODULE_PALETTE
    companyColor(key)       — index into 10-color COMPANY_PALETTE
    hexToRgba(hex, alpha)   — hex string → rgba(…) string

yamlUtils.ts
  Fetch + parse YAML from /public/data/:
    loadEnvConfig(datasetId) → RawEnvConfig
    loadSchedule(datasetId)  → RawSchedule
  Uses js-yaml for parsing. Constructs URL from APP_CONFIG paths.

excelExport.ts
  Export Gantt to .xlsx (mirrors yaml_to_suother_like_excel.py output):
    exportGanttToExcel(ganttData, filename) — async, triggers browser download
  Uses ExcelJS for styled output: merged month headers (blue background), day/weekday rows,
  frozen panes (first 4 cols + 3 rows), per-cell fill colors, cut-off border (medium blue),
  today border (medium orange), unavailable cells (red fill), weekend cells (grey fill).
  Uses file-saver saveAs() for the browser download.

src/services/
--------------------------------------------------------------------------------
databaseService.ts
  Reads database.xlsx from /public/data/ via fetch + SheetJS.
  Caches parsed data in localStorage (TTL: 5 min) and in-memory.
  Falls back to mockData if file not found.
  Exports: loadDatabase, getDatasets, getRunLogs, getComments, addComment, clearCache.

ganttService.ts
  TypeScript port of yaml_to_suother_like_excel.py:
    buildGanttData(env, sched) → GanttData
  Key internal functions:
    parseUnavailDates(raw, planStart, planEnd) — handles plain strings, {date:…},
      {single:{days:[…]}}, {single:{start,end}}, {weekly:{weekdays:[…]}}
    buildTaskModuleIndex(tasks)               — Map<taskId, moduleCode>
  Builds employee rows, unavail sets, workDate maps, and the full cell grid.

runService.ts
  Solver job submission and status polling (kept for the future live backend).
  submitRun(form)         — POST to apiBaseUrl/runSolver (dev mode: returns mock runId)
  pollRunStatus(runId)    — GET apiBaseUrl/status/{runId}

runStore.ts  ← mock "filesystem" for runs (localStorage)
  The browser-only store the UI actually talks to. Seeds demo runs on first load.
    listRuns()              — all runs, newest first
    getRun(id)              — one run
    createRun({...})        — new folder + run-log row (input files only)
    markFetched(id)         — mark output/ as fetched (output='ready')
    resetRuns()             — restore the seed runs
  Each Run.datasetId, if set, links to /public/data/datasets/<id>/ so the Gantt
  renders REAL YAML; if null, the Gantt uses the mock fallback grid.

--------------------------------------------------------------------------------
src/hooks/
--------------------------------------------------------------------------------
useDatasets.ts
  Fetches all datasets on mount. Exposes { datasets, loading, error, reload }.

useRunLog.ts
  Fetches run logs + comments for a given datasetId.
  Exposes { runLogs, comments, loading, error, submitComment, reload }.
  submitComment() appends via databaseService.addComment (session-only persistence).

useTimer.ts
  Live elapsed timer. Takes startEpoch (ms). Updates every second.
  Exposes { elapsedSeconds, timerLabel }. Cleans up interval on unmount.

useGantt.ts
  Builds Gantt data for a run.
    datasetId set  → fetch real EnvConfig.yaml + Schedule.yaml, then buildGanttData
    datasetId null → mock fallback: feed MOCK_ENV_CONFIG + MOCK_SCHEDULE through
                     the SAME builder (so the fallback exercises the real port)
  Exposes { ganttData, loading, error, isMock }.

useRuns.ts  ← run-log state hook (wraps runStore)
  Exposes { runs, refresh, addRun, fetchOutput }.
  fetchOutput(id) simulates a ~1.8s cloud download into the output/ folder.

src/pages/
--------------------------------------------------------------------------------
RunLogPage.tsx  ← landing page
  The run log. One row per run (= one local folder). 3 columns:
    1. Solve Date    — date/time + folder path (./runs/<id>/)
    2. Input Files   — EnvConfig + Schedule chips, [Path] popup, [Gantt] button
    3. Result        — empty: [Fetch Result] (mock ~1.8s download) + disabled Gantt
                       ready: [Output] path + [Gantt] (enabled only if outputHasYaml)
                              + "Files ready" tag
  No status badges (no status storage — out of plan).
  "New Run" button opens a modal with 2 file inputs (EnvConfig + Schedule).
  On submit → runStore.createRun() makes a new folder + row.
  Path button shows a dark tooltip popup with the local path (auto-hides 3s).

GanttPage.tsx
  Full Gantt chart for one run (route /gantt/:runId[/:view]).
  Looks up the Run, then useGantt(run.datasetId) → real YAML or mock fallback.
  - GanttTable: 3-row sticky thead (month, day, weekday) + employee tbody.
  - Month header merged + blue. Weekend grey. Cutoff blue right border.
    Today orange left border. Work cells colored by module. Unavailable red.
  - Left columns (Company, Name, Role, Mgr) are position:sticky.
  - GanttLegend: module swatches + Unavailable/Weekend/Cutoff/Today markers.
  - "Download Excel" button calls exportGanttToExcel.
  - Mock badge shown when rendered from the mock fallback.
  - New Run panel at the bottom (collapsible): REUSES this run's input files with
    new plan settings (plan start/end, cut-off, solver stage, lock/warm/overtime),
    Review & Confirm → Submit → creates a new run via runStore.createRun().

SettingsPage.tsx
  Local prototype settings: shows the solver API base URL, and a
  "Reset run store" button (restores the seed runs in localStorage).

================================================================================
SETUP
================================================================================
1. Install dependencies:
   cd webapp
   npm install

2. (Optional) Generate database.xlsx:
   npm run seed

3. Start dev server:
   npm run dev
   → http://localhost:5173

4. Build for production:
   npm run build

5. Set solver API URL (for live runs):
   Create .env in webapp/:
     VITE_API_BASE_URL=https://your-cloud-run-api.run.app
