# Result 2026-05-25 — Scheduler optimization: before vs after

  

**normal = before** (original constraints) · **shadow = after** (shadow variable + flatten)

  

Both runs use the **same input data** and the **same solver**, so they produce the

**same sequence of best-solution events** ("calculations"). Only the wall-clock time

needed to reach each event differs. The numbers below are the elapsed time in **Stage 1**

to reach the *N*-th best-solution event (Stage 1 reaches ~8,040 events in both runs).

For the first ~100 events the after-version is marginally slower (JIT warm-up, the

first snapshot is logged a few seconds later). From ~500 events onward it is several

times faster, and the gap widens as the search deepens and moves get more frequent.

  

## Techniques added

  

- **Shadow variable** — a cached list on each work block (`coveredWorkingDays`) that is

  recomputed only when the block's start day or length changes, so constraints reuse it

  instead of rebuilding the working-day span on every move.

- **Flatten (`flattenLast`)** — inside the constraint stream, one block is expanded into

  its individual working-day rows, so scoring touches only those days instead of joining

  every calendar day to every seat (the old cartesian product).
